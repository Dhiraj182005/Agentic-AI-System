4. PASSWORD HASHING
==================================================

Use a secure password hashing implementation.

Preferred:

Argon2 or bcrypt through a maintained Python security library.

Do NOT implement your own hashing algorithm.

Never store:

password
plain_password
raw_password

in the database.

Only store:

password_hash

Password requirements should be reasonable for an academic application.

At minimum:

- minimum length validation
- reject empty passwords
- reject obviously invalid input

Do not create absurdly complicated password rules.

6. JWT
==================================================

Implement JWT access tokens.

Token should contain appropriate information such as:

sub = user ID
exp = expiration time

Do not put sensitive information inside the JWT.

Configuration should come from environment variables.

Example:

JWT_SECRET_KEY=
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60

Do NOT hardcode the secret.

For development, `.env.example` can contain:

JWT_SECRET_KEY=change-me-in-development

but the real `.env` must not be committed.

==================================================
7. API ENDPOINTS
==================================================

Implement:

POST /api/v1/auth/register

POST /api/v1/auth/login

GET /api/v1/auth/me

--------------------------------------------------
REGISTER
--------------------------------------------------

Request:

{
    "email": "user@example.com",
    "password": "securepassword"
}

Response should return safe user information.

Example:

{
    "id": "...",
    "email": "user@example.com",
    "created_at": "..."
}

NEVER return password_hash.

If the email already exists:

Return an appropriate HTTP error such as:

409 Conflict

Do not leak unnecessary information.

--------------------------------------------------
LOGIN
--------------------------------------------------

Request:

{
    "email": "user@example.com",
    "password": "securepassword"
}

Response:

{
    "access_token": "...",
    "token_type": "bearer"
}

Use:

Authorization: Bearer <token>

for protected endpoints.

If credentials are incorrect, return an appropriate authentication error.

Do not reveal whether the email or password was specifically incorrect.

--------------------------------------------------
CURRENT USER
--------------------------------------------------

GET:

/api/v1/auth/me

Require:

Authorization: Bearer <token>

Return:

{
    "id": "...",
    "email": "...",
    "created_at": "..."
}

If the token is invalid or expired:

Return HTTP 401.

8. AUTHENTICATION DEPENDENCY
==================================================

Create a reusable FastAPI dependency such as:

get_current_user()

It should:

1. Extract Bearer token.
2. Decode JWT.
3. Validate signature.
4. Validate expiration.
5. Extract user ID.
6. Load user from PostgreSQL.
7. Return the User object.
8. Raise HTTP 401 if authentication fails.

Later modules should be able to use:

Depends(get_current_user)

without implementing authentication logic again.
