## 5. Scoring Rubric

Implement a documented, deterministic scoring formula.

Evaluate each participating agent on these seven dimensions, each scored from 0 to 10:

1. **Logical Soundness** — consistency, reasoning quality, and whether conclusions follow from arguments.
2. **Evidence Quality** — relevance, credibility, and usefulness of cited or retrieved evidence.
3. **Factual Support** — how well factual claims are supported by stored claim-verification results.
4. **Relevance** — how directly the arguments address the debate topic and opposing arguments.
5. **Effectiveness** — clarity, persuasiveness, and quality of responses and rebuttals.
6. **Completeness** — whether the agent addresses the important aspects of the topic and responds adequately to counterarguments.
7. **Fallacy Risk** — the degree to which detected logical fallacies weaken the arguments. A higher risk must reduce the final score.

### Default weights

Use these initial weights, and keep them in one clearly documented configuration:

- Logical Soundness: 20%
- Evidence Quality: 20%
- Factual Support: 15%
- Relevance: 15%
- Effectiveness: 10%
- Completeness: 10%
- Fallacy Risk: 10%

The first six dimensions contribute positively. Fallacy Risk is a penalty dimension, so transform it into a positive quality score:

`Fallacy Quality = 10 - Fallacy Risk`

Then calculate:

`Agent Score = 0.20 × Logical Soundness + 0.20 × Evidence Quality + 0.15 × Factual Support + 0.15 × Relevance + 0.10 × Effectiveness + 0.10 × Completeness + 0.10 × Fallacy Quality`

The result must be between 0 and 10.

Round only the final displayed score to two decimal places. Keep sufficient precision internally.

Do not allow the LLM to invent or independently modify the formula or weights.

If the existing Module 10 evaluation uses different criteria, document the mapping explicitly. Do not silently reinterpret existing fields.

## 6. Use Existing Evidence and Evaluation Data

The judge must reuse existing database records whenever available.

For each agent, collect:
- Debate messages and round order
- Extracted claims associated with its messages
- Stored claim-verification verdicts and confidence levels
- Retrieved evidence and source metadata
- Existing argument evaluations
- Existing fallacy detections

Follow the actual foreign-key relationships in the codebase.

### Factual support rules

- Use stored verification results and evidence, not unsupported model memory.
- Supported claims should contribute positively to factual support.
- Contradicted claims should reduce factual support.
- Insufficient-evidence claims must not be treated as true or false.
- Missing verification records must not be silently treated as supported.
- If evidence is unavailable, mark the relevant assessment as limited or unavailable.

### Fallacy rules

- Use stored fallacy-analysis results when available.
- Do not assume every detected fallacy makes the entire argument false.
- Consider severity, confidence, frequency, and context.
- Avoid counting the same fallacy repeatedly if the database contains duplicate detections.
- If fallacy analysis has not been run, report it as unavailable rather than assigning an unjustified low fallacy risk.

### Missing data

Do not fabricate evidence, citations, claims, verification results, fallacy results, or argument evaluations.

If the available data is insufficient for a reliable judgment, return a transparent limitation and an appropriate inconclusive outcome rather than manufacturing a winner.

## 8. Winner Selection Policy

Implement a transparent winner-selection policy.

- Only compare agents that actually participated in the debate.
- Use the deterministic final agent score.
- Require a configurable minimum score difference before declaring one agent the winner.
- If the top scores are too close, return a tie.
- If essential evaluation data is missing or unreliable, return inconclusive.
- Do not select a winner solely because an agent has more messages or uses more persuasive language.
- Do not present the highest-scoring agent as objectively correct or factually infallible.

Document the minimum score difference and make it configurable.

A winner is a recommendation based on the selected rubric, not a guarantee of truth.
